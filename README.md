# Potolok Planner

Планировщик и расчёт натяжных потолков.

## Что уже есть

- редактирование формы помещения;
- расчёт площади и периметра;
- добавление светильников, люстр и карнизов;
- каталог материалов и расчёт стоимости;
- варианты потолка;
- сохранение проектов в браузере;
- отдельная база клиентов (привязка проекта к клиенту, счётчик проектов);
- импорт и экспорт резервной копии;
- облачная синхронизация проектов и клиентов через Supabase (с удалением по обоим устройствам).

## Интеграция с CallRec

CallRec официально предоставляет REST API с JWT-авторизацией и позиционирует API как способ интеграции собственной CRM/веб-системы с данными аккаунта. В Potolok Planner добавлен серверный адаптер `lib/integrations/callrec.ts` и диагностический endpoint `/api/integrations/callrec/status`.

Секрет JWT хранится только на сервере в `CALLREC_JWT_TOKEN` и никогда не должен попадать в `NEXT_PUBLIC_*`. Конкретные пути ресурсов CallRec не захардкожены, поскольку публичная страница `/api-docs` в текущем окружении отдаёт только HTML оболочку без OpenAPI-схемы. После подтверждения актуального контракта можно безопасно добавить отдельные typed-методы для клиентов, проектов, товаров/услуг и других ресурсов.

### Переменные CallRec

```env
CALLREC_API_URL=https://callrec.net
CALLREC_JWT_TOKEN=YOUR_CALLREC_JWT_TOKEN
```

Проверка конфигурации:

```text
GET /api/integrations/callrec/status
```

## Запуск

```bash
npm install
npm run dev
```

После запуска откройте `http://localhost:3000`.

## Переменные окружения

Для функций Supabase используйте публичные переменные окружения приложения (`NEXT_PUBLIC_*`). Секретный service-role key нельзя помещать в клиентский код.

## Работа через Codex

Репозиторий подключён к GitHub, а инструкции для Codex находятся в `AGENTS.md`. Для каждой крупной функции рекомендуется работать отдельной веткой и открывать Pull Request в `main`.
